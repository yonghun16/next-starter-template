# Next.js 기초 교육 — terbotec-nextjs 프로젝트 기준

이 문서는 **현재 프로젝트 디렉터리 구조**를 바탕으로 Next.js의 동작 방식과 꼭 알아야 할 기초를 정리한 것입니다.

---

## 1. 프로젝트 디렉터리 구조 한눈에 보기

```
terbotec-nextjs/
├── src/
│   ├── app/                    ← ★ App Router (페이지·레이아웃·스타일)
│   │   ├── layout.tsx          ← 루트 레이아웃 (모든 페이지 공통)
│   │   ├── page.tsx            ← 메인 페이지 (/)
│   │   └── globals.css         ← 전역 CSS
│   └── utils/                  ← 유틸/헬퍼 (Supabase 클라이언트 등)
│       └── supabase/
│           └── client.ts
├── public/                     ← 정적 파일 (이미지, 아이콘 등)
│   ├── koreaterbotec-hero.png
│   └── ...
├── next.config.ts              ← Next.js 설정
├── package.json
└── ...
```

- **`src/app/`** 안에 있는 파일들이 **URL과 페이지**를 만듭니다.
- **`public/`** 안 파일은 그대로 URL로 제공됩니다. (예: `/koreaterbotec-hero.png`)

---

## 2. Next.js가 요청을 처리하는 방식 (대략적인 흐름)

1. 사용자가 **URL**로 접속 (예: `https://yoursite.com/`)
2. Next.js가 **어떤 페이지를 보여줄지** `src/app/` 폴더 구조로 결정
3. **layout.tsx**로 공통 틀(HTML, body, 폰트, 메타)을 감싼 뒤
4. 해당 경로의 **page.tsx** 내용을 `children` 자리에 넣어서 렌더링
5. 서버에서 HTML을 만들고(SSR), 필요하면 클라이언트에서 JS로 보강(hydration)

즉, **폴더 = URL 경로**, **파일 = 페이지/레이아웃** 이라고 보면 됩니다.

---

## 3. App Router — 폴더가 곧 라우트

Next.js 13+ 부터는 **App Router**가 기본입니다. **폴더 이름 = URL 경로**입니다.

| 파일 경로 | URL | 설명 |
|-----------|-----|------|
| `src/app/page.tsx` | `/` | 메인(홈) 페이지 |
| `src/app/about/page.tsx` | `/about` | 소개 페이지 |
| `src/app/products/page.tsx` | `/products` | 제품 목록 |
| `src/app/products/[id]/page.tsx` | `/products/123` | 동적 세그먼트 |

- **page.tsx** → 해당 경로의 “페이지” (반드시 이 이름이어야 함)
- **layout.tsx** → 그 경로와 하위 경로 전체에 공통으로 적용되는 레이아웃
- **loading.tsx** → 로딩 UI
- **error.tsx** → 에러 UI
- **not-found.tsx** → 404 페이지

지금 프로젝트에는 `app/page.tsx` 하나만 있으므로 **`/`** 만 페이지가 있고, 나머지 경로는 아직 없습니다. 새 페이지를 만들려면 `src/app/경로이름/page.tsx` 를 추가하면 됩니다.

---

## 4. 레이아웃(layout)과 페이지(page)의 관계

- **layout.tsx** 는 “공통 틀”입니다.  
  - `<html>`, `<body>`, 공통 헤더/푸터, 폰트, 메타데이터 등.
- **page.tsx** 는 “그 안에 들어갈 내용”입니다.  
  - layout의 `{children}` 자리에 page 내용이 들어갑니다.

현재 구조:

```
layout.tsx (루트)
  └── <html> → <body> → {children}
                          └── page.tsx (홈 전체 UI)
```

나중에 `/about` 페이지를 만들면:

- `src/app/layout.tsx` → 그대로 전체 공통
- `src/app/about/page.tsx` → `/about` 일 때만 `children`이 이 내용으로 바뀜

---

## 5. 서버 컴포넌트 vs 클라이언트 컴포넌트

Next.js는 기본적으로 **모든 컴포넌트를 서버 컴포넌트**로 취급합니다.  
즉, **서버에서 먼저 실행**되고, HTML이 만들어져 내려옵니다.

- **서버 컴포넌트**
  - `useState`, `useEffect`, `onClick` 같은 **브라우저 전용 API 사용 불가**
  - DB/API 호출을 서버에서 직접 할 수 있어서 **보안·성능**에 유리
  - 파일 상단에 아무것도 안 쓰면 서버 컴포넌트

- **클라이언트 컴포넌트**
  - **`'use client'`** 를 파일 **맨 위**에 한 줄 쓰면 됨
  - `useState`, `useEffect`, 이벤트 핸들러, 브라우저 API 사용 가능
  - 상호작용(버튼 클릭, 폼 입력 등)이 필요한 UI에 사용

지금 **`src/app/page.tsx`** 맨 위에 `'use client'` 가 있기 때문에 이 페이지는 **클라이언트 컴포넌트**로 동작합니다.  
(히어로 화살표 버튼 등 상호작용이 있을 수 있어서 그렇게 둔 상태로 보입니다.)

정리:

- 상호작용이 없고, 데이터만 보여주면 → 서버 컴포넌트 유지
- `useState` / `onClick` / `useEffect` 등이 필요하면 → 해당 컴포넌트만 `'use client'` 로 분리하는 것이 좋습니다.

## 6. 메타데이터(SEO)

`src/app/layout.tsx` 에서:

```ts
export const metadata: Metadata = {
  title: "Create Next App",
  description: "Generated by create next app",
};
```

이것이 **전체 사이트 기본** `<title>`, `<meta name="description">` 등을 정합니다.  
페이지마다 다르게 하려면 각 **page.tsx**에서 `metadata` 를 export 하면 됩니다.

```ts
// src/app/page.tsx (서버 컴포넌트일 때)
export const metadata = {
  title: "코리아터보텍",
  description: "코리아터보텍 공식 홈페이지",
};
```

(현재 page.tsx는 `'use client'` 라서 여기선 metadata 대신 layout에서 title/description을 바꾸거나, 나중에 서버 페이지를 두고 그쪽에서 metadata를 넣을 수 있습니다.)

## 7. 정적 파일(이미지, 폰트 등)

- **public 폴더**
  - `public/koreaterbotec-hero.png` → 배포 후 `https://도메인/koreaterbotec-hero.png` 로 접근
  - HTML/CSS에서는 `url('/koreaterbotec-hero.png')` 처럼 **경로는 `/` 로 시작**

- **이미지 최적화**
  - `<img>` 대신 Next.js의 **`<Image>`** (`next/image`) 를 쓰면 자동 리사이즈·최적 포맷·lazy load가 적용됩니다.
  - 나중에 성능 신경 쓸 때 도입하면 좋습니다.

---

## 8. 환경 변수

- `.env.local` 에 넣은 값은 **서버/클라이언트**에서 사용 가능합니다.
- **브라우저에 노출해도 되는 값**만 `NEXT_PUBLIC_` 접두사를 붙입니다.  
  예: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- `src/utils/supabase/client.ts` 에서 이렇게 사용 중입니다:

```ts
process.env.NEXT_PUBLIC_SUPABASE_URL!,
process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
```

절대 서버만 쓰는 비밀키는 `NEXT_PUBLIC_` 없이 두고, 서버 코드에서만 `process.env.변수명` 으로 사용하세요.

## 9. 스타일링 (지금 프로젝트 기준)

- **globals.css**
  - `src/app/layout.tsx` 에서 `import "./globals.css"` 로 한 번만 불러오면 전역에 적용됩니다.
  - 지금 쓰는 `koreaterbotec-*` 클래스들이 여기 정의되어 있습니다.

- **Tailwind**
  - `package.json` 에 `tailwindcss` 가 있고, `postcss.config.mjs` 로 PostCSS가 연결되어 있습니다.
  - 원하면 `className="flex gap-4 text-red-600"` 처럼 유틸리티 클래스를 바로 사용할 수 있습니다.
  - 기존에 작성한 전역 CSS와 섞어 써도 됩니다.

## 10. 알아두면 좋은 것들 (체크리스트)

| 항목 | 설명 |
|------|------|
| **App Router** | `src/app/` 아래 폴더 = URL, `page.tsx` = 페이지 |
| **layout / page** | layout은 공통 틀, page는 그 경로의 내용 |
| **'use client'** | 상호작용·훅이 필요할 때만 해당 파일 상단에 작성 |
| **서버 우선** | 기본은 서버 컴포넌트; 클라이언트는 필요한 부분만 |
| **public** | 정적 파일은 `public/` 에 두고 경로는 `/파일명` |
| **환경 변수** | 브라우저 노출용만 `NEXT_PUBLIC_` |
| **메타데이터** | layout 또는 page에서 `metadata` export 로 SEO 설정 |

## 11. 다음 단계 제안

1. **새 페이지 추가**
   - `src/app/about/page.tsx` 를 만들고 간단한 내용 넣은 뒤 `/about` 접속해 보기.
2. **레이아웃 활용**
   - 공통 헤더/푸터를 `layout.tsx` 로 옮기고, `page.tsx` 는 본문만 담게 나누어 보기.
3. **라우팅**
   - `<a href="/about">` 또는 Next.js의 `<Link href="/about">` (`next/link`) 로 페이지 이동해 보기.
4. **클라이언트 분리**
   - 버튼·폼처럼 상호작용이 필요한 부분만 별도 파일로 빼서 `'use client'` 적용해 보기.

이 문서는 현재 디렉터리 구조를 기준으로 했으므로, 폴더나 파일이 바뀌면 이 구조를 기준으로 다시 읽어보면 됩니다.
